## 2. 数据模型

### 2.1 文档登记（SQLite `data/state/catalog.sqlite` 的 `documents` 表）

| 字段 | 类型 | 说明 |
|---|---|---|
| doc_id | TEXT PK | `doc-<sha256 前12位>` |
| title | TEXT | 制度名称 |
| doc_no | TEXT | 文号，如 `校发〔2024〕12号`，可空 |
| version_label | TEXT | 版本，如 `2024修订版`，可空 |
| effective_from | TEXT | 生效日期 `YYYY-MM-DD`，可空 |
| effective_to | TEXT | 废止日期，可空（空=现行） |
| department | TEXT | 归口部门，可空 |
| status | TEXT | `active` / `superseded` / `repealed`，默认 `active` |
| supersedes | TEXT | 本文件代替的旧文档 doc_id，可空（发布时按版本链自动填或 API 手工覆盖） |
| superseded_by | TEXT | 替代本文件的文档 doc_id，可空（旧版被自动置为 `superseded` 时写入） |
| file_name | TEXT | 原文件名 |
| format | TEXT | `pdf` / `docx` / `md` / `txt` |
| pages | INTEGER | 页数（docx 记 1） |
| has_pdf | INTEGER | 1/0，前端是否可预览原页：PDF 原件，或 DOCX 由 Word 转出的 `source.pdf` |
| sha256 | TEXT | 原文哈希，用于去重 |
| source_path | TEXT | `data/docs/<doc_id>/source.<ext>` |
| imported_at | TEXT | ISO 时间 |

### 2.2 知识单元 unit（`data/docs/<doc_id>/units.jsonl`）

```json
{
  "id": "doc-3f2a9c1b7d40#u0007",
  "doc_id": "doc-3f2a9c1b7d40",
  "doc_title": "XX大学实验室安全管理办法",
  "doc_no": "校发〔2024〕12号",
  "version_label": "2024修订版",
  "effective_from": "2024-07-01",
  "effective_to": null,
  "department": "实验室与设备管理处",
  "status": "active",
  "chapter": "第三章 危险化学品管理",
  "section": null,
  "article": "第十二条",
  "article_no": 12,
  "kind": "article",
  "heading_path": ["第三章 危险化学品管理", "第十二条"],
  "text": "原文……",
  "pages": [3],
  "table": null,
  "order": 7,
  "source": {"doc_id": "doc-3f2a9c1b7d40", "file": "实验室安全管理办法.pdf", "page": 3, "page_end": 3, "parser": "pymupdf"}
}
```

- `kind` 取值：`article`（条款）/ `section`（章节导语）/ `paragraph`（无条款号的正文）/ `table_row`（表格行）/ `attachment`（附件）。
- `text` 必须是原文连续片段，不改写、不总结。
- `pages` 为原页物理页（从 1 开始）：pdf 按实际页数；docx 在 `POLICYRAG_DOCX_PREVIEW=1` 且本机有 Word 时按转换后 PDF 的实际页数，否则记 `[1]`；md/txt 记 `[1]` 且 `has_pdf=false`。
- `table_row` 时 `table = {"name": "报销标准", "headers": ["项目","标准"], "row": ["差旅","300元/天"]}`。
- 单元 `id` 在文档内稳定：`<doc_id>#u<order:04d>`。

### 2.3 检索片段 passage（发布时生成，`data/releases/<release>/passages.jsonl`）

```json
{"id": "p_000001", "unit_id": "doc-...#u0007", "text": "片段原文", "embedding_text": "《XX办法》第十二条 片段原文", "start": 0, "end": 420}
```

- 按 448 token 切、64 token 重叠（token 用 BGE 分词器计）。
- `embedding_text` = 文档标题 + 条款号 + 片段文本；编码用它，证据展示用 `text`。

### 2.5 检索结果（`PolicyRetriever.search` 返回值）

```json
{
  "question": "实验室危化品怎么领用？",
  "rewritten": "实验室危险化学品领用流程",
  "filters": {"department": null, "as_of": "2026-10-21"},
  "results": [
    {"rank": 1,
     "unit": { "...unit 全字段..." },
     "evidence": "用于提示词的证据原文（含章节/条款抬头）",
     "citation": {"doc_id": "...", "title": "...", "doc_no": "...", "article": "第十二条",
                  "chapter": "第三章", "page": 3, "pages": [3], "version_label": "2024修订版"},
     "channels": ["BGE", "BM25"],
     "scores": {"dense": 0.8123, "bm25": 6.42, "rrf": 0.0328}}
  ],
  "context": "[证据1] 《XX办法》第三章 第十二条（第3页）\n原文……\n\n[证据2] ……",
  "tokens": 1830,
  "notes": ["《XX办法》2025修订版自2025-09-01起施行，旧版内容仅作参考"],
  "seconds": 0.42
}
```

- `results` 最多 `top_k` 条；`context` 受 `config.MAX_CONTEXT_TOKENS` 限制，超限条目丢弃并在 `notes` 说明。
- 只返回 `status != repealed` 的单元；同主题存在更新版本时，旧版本默认**不进入证据**（用户明确点名旧文号时除外），只在 `notes` 提示。
- 相关性闸门：最佳向量相似度低于 `config.RETRIEVAL_MIN_DENSE`（默认 0.45，`0` 关闭）且没有条款号/文号/章节/标题精确命中时，返回 `results: []`、`context: ""`，并在 `notes` 说明“未找到与问题直接相关的制度条款”，避免拿低分结果硬凑引用。
- 单条结果同样过闸：向量分低于阈值、BM25 又不强、也不是精确命中的条目会被丢弃，避免回答里出现无关文档的引用。
- 重排：RRF 融合与硬过滤之后、多样性选择之前，用 `bge-reranker-v2-m3` 对排序前 `RERANK_TOP_N`（默认 20）个候选做交叉编码打分重排，分数写入 `results[].scores.rerank`。
  模型目录由 `POLICYRAG_RERANK_MODEL_DIR` 指定（默认 `models/bge-reranker-v2-m3`），`POLICYRAG_RERANK=0` 关闭；
  模型缺失或加载失败时记录一条 warning 并回退原排序，问答不受影响。
- 表格证据格式：`table_row` 单元渲染为「表格：… / 列：… / 行：…」；条款以冒号或「如下」结尾时，检索器会把紧邻的表格行并入该条款证据（这些行不再单独占证据位）。
- 数值/期限优先（T8）：问题或改写问句含「3个工作日 / 三个月 / 650元 / 80％」这类数值时，检索器在排序前把**正文命中该数值**的候选提到重排窗口前部（`app.retrieval.ranking.prefer_numeric_units`，窗口 20），并把并入表格中命中该数值的行排到「列：」之后的第一行；正文不改写、不重排，证据数不增加。
- 同条款合并（T8）：同一 `(doc_id, chapter, section, article)` 的多个单元只占一个证据位，正文按原顺序拼接（`ranking.merge_article_units`），`results[].merged_units` 记录被并入的 unit id，`citation.pages` 取并集。
- 版本提示只在「问题本身在问版本/有效性」（含“有效/现行/旧版/新版/修订/废止/版本/之前/原来”等词）或用户点名旧文号时输出，避免每次回答都带一句无关提示。

### 3.2 `app.ingest.parser`

```python
def parse_document(path: Path) -> dict
# {"format": "pdf", "pages": [{"no": 1, "text": "..."}, ...], "has_pdf": true, "page_count": 12}
# PDF 用 pymupdf；docx 用 python-docx（表格另取）；md/txt 按空行/标题切节，page 固定 1
```

可选字段（按需出现，解析器契约向后兼容）：

| 字段 | 出现条件 | 含义 |
| --- | --- | --- |
| `parser` | 始终 | `pymupdf` / `python-docx` / `text` / `html.parser` / `docling` |
| `ocr_pages` | 任意页走过 OCR | 本次 OCR 的页数 |
| `pages[].ocr` | 该页由 OCR 产出 | `true`；`pages[].ocr_meta` 记录端点耗时 |
| `pages[].ocr_issues` | OCR 页质量检查未过 | 问题码：`empty_or_very_short` / `unclosed_html_table` / `repeated_long_lines` / `repeated_long_spans`，质量检查会转成不阻断的 `ocr_quality` 提示 |
| `docling_tables` / `docling_seconds` | `POLICYRAG_PARSER_PDF=docling` | 表格数与解析耗时 |

扫描件兜底：文本层少于 `OCR_MIN_CHARS`（默认 20）的页，用 PyMuPDF 渲染
`OCR_DPI`（默认 200）PNG，POST 到 `POLICYRAG_OCR_ENDPOINT`（multipart 字段 `image`，
返回 `{"code": 0, "result": "markdown"}`），成功则替换该页文本；端点未配置时保持原行为。

docling 后端：`POLICYRAG_PARSER_PDF=docling` 时由 `POLICYRAG_DOCLING_PYTHON`
（默认同盘 RAG 项目的 parse 运行时）执行 `scripts/docling_worker.py`，
模型目录 `POLICYRAG_DOCLING_ARTIFACTS`（默认同盘 RAG 的 `model/docling`），
整份 PDF 一次转换、按页返回 markdown（表格为 pipe 表格，可直接切 `table_row`）。
失败原因以中文 `RuntimeError` 抛给入库任务。

DOCX 页图：入库时（`POLICYRAG_DOCX_PREVIEW=1`，默认开）用 PowerShell 调 Word COM
把原文另存为 `data/docs/<doc_id>/source.pdf`（`POLICYRAG_DOCX_PREVIEW_TIMEOUT` 默认 120s），
成功则 `has_pdf=1`、`pages` 取 PDF 实际页数；失败只追加一条不阻断的 `docx_preview` 提示，
文本入库照常。非 Windows 或无 Word 的环境自动跳过。历史文档可用
`python scripts/docx_preview.py` 补页图（`--force` 重转）。

### 3.11 `app.retrieval.engine`

```python
class PolicyRetriever:
    def __init__(self, release_dir: Path, backend: str = "chroma", device: str | None = None,
                 catalog_path: Path | None = None)
    device: str
    def search(self, question: str, top_k: int = 5, filters: dict | None = None,
               on_stage: Callable | None = None) -> dict
    def info(self) -> dict
```

`on_stage(stage: str, payload: dict)` 会被服务层用来推 SSE，取值：`query` / `vectors` / `keywords` / `evidence`。

检索结果缓存（T9）：`PolicyRetriever.search` 在查询拆解后先查 LRU 缓存，
键为 `release_id + 规范化问题 + 过滤条件（排序后、空值剔除）+ 基准日 + top_k`；
命中时仍推送 `query` / `evidence` 事件，返回结果带 `cached: true` 与本次耗时，
不会重复编码、融合与重排。容量 `RAG_CACHE_SIZE`（默认 256），换发布/换过滤/换基准日自然失效；
`/api/info` 的 `cache` 字段返回命中统计。

检索前会先做一次查询拆解（`app.retrieval.planner.plan_query`）：用户原话里出现
「分别 / 各自 / 同时 / 以及 / ；」这类连接词时，拆成多个子句分别召回，再用 RRF 求和
并给每个子问题保留至少一个证据位；拆解结果通过 `query` 事件的 `sub_queries` 字段返回
（单话题时为空数组）。

OpenAI 兼容 `/chat/completions`，`stream=True` 逐行解析 `data: {...}`；异常统一抛 `RuntimeError("生成模型不可用：...")`。
韧性（T11）：连接错误 / 5xx / 429 / 首 token 超时按 `retries` 指数退避重试（默认 2 次，`RAG_LLM_RETRIES`）；
已输出 token 后的中断**不重试**（避免重复内容），报「回答未完成：…」；首 token 等待上限 `RAG_LLM_FIRST_TOKEN_TIMEOUT`（默认 60s）。

### 3.14 可观测性（`app/observability.py`）

每次 `/api/ask` 结束（含错误）写一行 JSON 到 `data/logs/app.log`：
`request_id`、`at`、`question`、`route`（retrieve/chat）、`routing_ms`、`retrieval_ms`、
`first_token_ms`、`total_ms`、`sources`、`error`。同一份记录进入进程内 `Metrics`
（最近 500 次），`GET /api/metrics` 返回请求数、错误率与总耗时/检索/首 token 的 P50·P95。
日志写入失败不影响问答（只记 warning）。

## 4. HTTP API

统一前缀 `/api`，错误返回 `{"detail": "中文说明"}`。

## 5. 约定与红线

1. 不改写原文；所有证据必须能在 `units.jsonl` 找到。
2. 检索/生成失败必须返回明确中文错误，不能静默编造。
3. 不新增重型依赖（pandas、langchain、faiss 都不装）；确需新增先说明。
4. 所有写文件用 UTF-8；原子写用 `.tmp` + `os.replace`。
5. 单测不依赖外部网络与真实大模型；LLM 用假客户端。
6. 目录内只写自己的文件；共享文件（`app/main.py`、`app/config.py`、本文档）由 Lead 维护。
