## 原则

- 只做通用改动，不做逐题特判；q10 用重排 + 证据覆盖解决，不在提示词里写死「3 个月」。
- 不增加无意义测试：每项最多补 1–3 条契约级测试；改动前跑现有 121 条测试。
- QA 延迟预算：默认路径额外开销 ≤ 200ms；重的解析（OCR/docling）只进异步入库，不进问答链路。
- 能用 GPU 用 GPU：重排在 5070 上 fp16；docling/OCR 可用 CUDA；CPU 更快的自动留 CPU。
- 启动的服务/网页只用于验证，验证完立即关闭。

## 执行协议（每项）

1. 记基线：相关测试 + （涉及检索/生成时）40 题评测 + 延迟。
2. 改动：只动该任务范围；接口变化先更新 `docs/架构与接口.md`。
3. 验证：`pytest tests -q`；40 题评测对比；启动服务只用于验证，结束立即停止并确认端口释放。
4. 提交：独立 commit，提交信息带实测数字。
5. 汇报：一句话结论 + 数字 + 遗留风险，然后继续下一项。
